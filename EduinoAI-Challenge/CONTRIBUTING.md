# 함께 고칠 때 지키는 것

이 저장소는 수업에서 쓰는 물건이다. 배포본이 곧 교실 화면이므로,
고치는 절차를 좁게 잡는다. 아래 네 가지만 지키면 된다.

## 1. 가지(branch)

- `main` 은 **배포 전용**이다. `main` 에 직접 커밋하지 않는다.
- 작업은 `feature/<차수>-<한마디>` 로 새 가지를 판다.
  예) `feature/58-b-hub-list`, `feature/59-a-motor-trim`
- 합치는 길은 PR 하나뿐이다.

## 2. PR 본문

두 절만 적는다. 그 밖의 것은 적지 않는다.

```
[작업 범위]
- 무엇을 어디까지 손댔는지

[기준과 다르게 한 부분]
- 지시·문서·기존 기준과 다르게 간 자리와 그 이유
- 없으면 "없음"
```

## 3. 올리기 전에 검사

```
node tools/checks/run-all.mjs
```

전부 통과해야 PR 을 연다. 실패가 남아 있으면 올리지 않는다.
`skip` 이 있으면 PR 본문에 사유를 한 줄로 적는다.

## 4. 검사가 못 잡는 넷은 눈으로 본다

레이아웃이 자리를 잡는 과정에서 나는 결함은 로컬 검사에 걸리지 않는다.
로컬에서는 뒤이은 렌더가 잘못된 값을 스스로 고쳐 버리고, 배포본에서는
그 보정이 오지 않아 값이 굳는다. 이 프로젝트에서 여섯 번 났다.

그래서 아래 넷은 **배포본에서 사람이 직접 본다.**

- **첫 화면** — 요소가 최종 자리를 잡기 전에 크기를 재는 자리
- **에셋 도착** — 늦게 오는 이미지·시트가 화면에 반영되는 순간
- **저장 상태** — 브라우저에 남아 있던 코드·기록이 새 판을 밀어내는 경우
- **목록 생성** — 허브·라우터·폴백이 서로 다른 목록을 보는 경우

로컬 검사가 통과했다는 사실은 배포본이 멀쩡하다는 뜻이 아니다.
확인하지 못했으면 PR 본문에 `[배포본] 측정 없음` 을 적는다.
자세한 배경은 `docs/REGRESSION.md` 에 있다.

## 되돌리기 어려운 것은 먼저 묻는다

파일을 지우거나 옮기는 일, 공개 주소·저장 키를 바꾸는 일, 기록을 지우는 일은
진행하기 전에 질문한다. 임의로 진행하지 않는다.

- 하드삭제 API 를 만들지 않는다. 소프트삭제만 쓴다.
- 물리·랩타임·결정론 코드는 손대지 않는다.
- 챌린지의 수치·문구·규칙은 매니페스트가 소유한다. 코드에 박지 않는다.
- 표시 이름(닉네임)만 받는다. 실명을 유도하지 않는다.
- 영상·원본 이미지를 저장하거나 밖으로 보내지 않는다.
