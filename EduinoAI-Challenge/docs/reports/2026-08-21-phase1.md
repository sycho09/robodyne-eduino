## 3. 확정 사항 반영

| 결정 | 반영 위치 |
| --- | --- |
| 좌표계 = mm 실측 고정 (x 오른쪽, y 위, CCW +) | `scene.units` 는 값 1개짜리 enum이라 단위 혼용 불가 |
| tick = 10ms / 100Hz | `TICK_MS` 는 **엔진 상수**. 매니페스트에서 변경 불가 (과거 랩타임 비교 보전) |
| 트랜스파일 = 자체 파서 → JS generator | 모든 함수를 generator로 변환. delay가 몇 겹 안쪽이어도 tick 소비, 엔진이 실행을 통제 |
| 모터 상태 지속 + 이상화 물리 | `moveForward()` 는 상태만 변경, 이동량은 `delay()` 가 결정 |

부수 효과: heading을 milli-degree **정수**로 누적해 90° 회전이 오차 없이 정확히 떨어짐.

## 4. 판단해서 진행한 것 — 승인/수정 필요

| # | 내용 | 이유 | 되돌리는 비용 |
| --- | --- | --- | --- |
| A | **아웃랩 도입**: 출발점이 코너라, 결승선(윗변 중앙)을 처음 통과할 때부터 랩 계측 시작 | 스타터 코드가 `4 × (전진 + 우회전)` 로 깔끔해지고 랩타임이 정확히 18.000초로 떨어짐 | 낮음 (매니페스트 spawn/checkpoint 수정) |
| B | **`loop()` 최소 1 tick 규칙**: loop 한 바퀴가 tick을 하나도 안 쓰면 강제로 1 tick 소비 | 멈춤 방지. delay를 제대로 쓴 코드에는 발동하지 않아 랩타임 왜곡 없음 | 낮음 |
| C | `limits.wall_clock_ms` → **`max_catchup_ms`** 로 이름·의미 변경 | 실제 경과시간으로 시도를 끊으면 느린 PC에서 결과가 달라져 결정론이 깨짐. 타임아웃은 tick 기준 `max_sim_ticks` 담당 | 낮음 |
| D | 차량 스펙을 챌린지와 분리해 `kits/*.json` 으로 소유 | 킷이 늘어도 챌린지 매니페스트를 안 건드림. 트랙 폭 = 차폭×3 검증을 로더가 자동 수행 | 중간 |
| E | 궤적(trail) 표시 | 학생이 자기 주행 경로를 눈으로 확인 가능 | 낮음 |
