# RC카 콘텐츠 마감 요약 (50차)

ESP32-CAM 2WD 킷의 RC카 콘텐츠는 50차로 닫는다. 이 문서 한 장이 지금 무엇이 있고,
무엇을 지켜야 하고, 무엇이 남았는지를 담는다. 다음 사람이 여기부터 읽으면 된다.

## 계열 3개 · 챌린지 8종

계열은 카탈로그(`src/challenges/index.json`)의 `series` 가 소유한다. 허브는 계열로 묶고
계열 안에서 난이도 순으로 세우며, 아직 목표를 못 넘긴 것 가운데 가장 앞에 "여기부터" 를 붙인다.

## 목표 시간을 정하는 방침

`docs/REGRESSION.md` 의 "목표 시간을 정하는 방침" 에 있다. 요약하면
**초급은 해답으로 달성 가능하게, 중급부터는 해답 기록의 92~96% 선**이다.
값을 바꾸면 `node tools/checks/laptime.mjs` 로 해답 기록을 다시 재고 표로 확인한다.

## 확립된 화면 표준

- **3분할 셸** — 왼쪽 코드 에디터 · 가운데 시뮬레이션 · 오른쪽 계기와 기록.
  코드가 없는 챌린지(`smartcity-drive`)는 왼쪽을 관제 대시보드로 바꾼다(`scene.layout`).
- **오른쪽 열 차례** — 카메라 시점 → 모터 상태 → 전체뷰 → 기록 → 규칙.
  카메라를 안 쓰는 챌린지에서는 첫 칸이 DOM 에서 빠져 모터 상태가 맨 위로 온다.
- **목표 배너** 네 칸 — 이번 챌린지 · 제한 시간 · 실패 조건 · 기록 인정.
  칸 이름도 값도 매니페스트(`scene.ui.goal_banner`)가 소유한다.
- **결과 모달** — 주행이 끝나는 순간 도장(`✓ 목표 달성` / `완주`) · 기록 · 이전 대비 ·
  왜 그런지 한 줄 · 상세 수치 · 저장 버튼이 한 화면에 있다.
- **목표 시간 표기** — 목표는 소수점 뒤의 0 을 떼고("15초", "16.5초"), 기록은 tick 정밀도
  그대로 소수 셋째 자리까지 적는다("15.820초"). 허브·배너·결과 모달이 같은 규칙을 쓴다.
- **한국어 줄바꿈** — `word-break: keep-all` · `overflow-wrap: break-word` ·
  `line-break: strict` 를 전역으로 둔다. 코드 에디터만 예외다.
- **브레드크럼** — 킷이 하나뿐이면 첫 화면이 곧 그 킷의 챌린지 목록이고, 킷 조각을 넣지 않는다.
  킷이 둘 이상이 되면 "킷 고르기" 화면이 저절로 돌아온다.
- **배경** — 계열마다 다른 공간으로 굽는다(레이스장 · 물류창고 · 도시).
  테마는 매니페스트(`scene.theme`)가, 소품의 종류·자리·크기·색은 `scene.props` 가 소유한다.
  노면은 코스 밖보다 항상 1.5배 이상 밝고, 코스 밖의 어떤 지점도 노면보다 밝지 않다.
  소품이 테마를 알려주는 일은 형태가 한다 — 밝기로 하지 않는다.

## 절대 원칙

차수마다 다시 적어 온 것들이다. 하나라도 어기면 그 차수는 실패로 본다.

1. **실물에 없는 API 를 만들지 않는다.** 규격서는 `docs/API-COMPATIBILITY.md` 다.
   코드·API 용어는 실물 그대로 둔다(`setMotor`, `PWM`, `delay`, `analogWrite` …).
   바꿀 수 있는 것은 화면 문구뿐이다.
2. **하드삭제 금지.** 챌린지도 기록도 지우지 않는다. 목록에서 내릴 뿐이다.
3. **수치를 지어내지 않는다.** 화면과 보고서의 모든 숫자는 엔진이나 검사 도구가 낸 값이다.
4. **비주얼은 에셋 슬롯만.** 코드로 그림을 그리지 않는다. 배경·스프라이트는 빌드 단계에서
   굽고 결과 파일만 커밋한다(앱 실행에 Blender 는 필요 없다).
5. **고정 timestep 10ms · 고정 시드 · 난수 금지.** 웹캠 입력만 예외다.
6. **물리·랩타임·결정론 코드는 건드리지 않는다.** `src/engine`, `src/runtime` 이다.
7. **영상·원본 이미지를 저장하거나 보내지 않는다.** 학습 샘플은 특징값만 남는다.
8. **실명 입력을 유도하지 않는다.** 표시 이름(닉네임)만 받고 브라우저에만 저장한다.
9. **챌린지는 데이터다.** 코스·마커·목표·난이도·요약·배우는 것·테마·소품은 전부
   매니페스트와 카탈로그에 있다. 화면 코드에 챌린지 이름을 박지 않는다.

## 검사 열

```
node tools/checks/run-all.mjs
```

선언 순서 · 목록 · 밝기 · 정렬 · 랩 tick · 렌더 · 콜드 캐시 · 화면 · 기록 있는 상태 · 옛 코드 있는 상태.
무엇을 보고 무엇이 실패인지, 어느 차수의 어떤 실패에서 나왔는지는 `docs/REGRESSION.md` 에 있다.
검사는 전부 "실제로 한 번 놓쳤던 것" 에서 나왔다. 새 검사도 같은 기준으로만 만든다.

| 404.html 과 셸 대조 정리 | 딥링크는 57-A 보강4에 해결됐다 — 원인은 vercel.json 의 `cleanUrls: true` 였고, 그것을 빼자 배포본이 HTTP 200 + `meta[dtc-shell]=index` 를 냈다(Root Directory·Production Branch 는 문제없었다). 그래서 404.html 폴백은 이제 없어도 된다. 다음 정리 차수에 지우고, 콜드 캐시 검사의 "셸 두 장의 자산 목록 일치" 항목도 그때 함께 정리한다. 시연 전에는 건드리지 않는다 |

| 좌우 개별 PWM 실측 | 모터 편차 과제(중급 이상)는 왼쪽·오른쪽에 다른 PWM 을 줄 수 있다는 데서 성립한다. 지금 근거는 킷 스펙의 `pins`·`wiring` 뿐이다 — 바퀴마다 제 핀 두 개, 네 핀이 서로 독립. 펌웨어 스케치가 이 저장소에 없어 실물에서 좌우에 다른 값을 넣어 재 본 기록은 아직 없다. 실물이 붙는 자리에서 한 번 재고 API-COMPATIBILITY 의 그 문단을 실측으로 바꾼다(57-D) |
