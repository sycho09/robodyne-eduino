## 1. 왜 했나

원 요구사항은 "빔프로젝터나 멀리서 볼 때도 UI가 눈에 띄도록 시인성 중심". 여기에
"지금 UI는 마음에 드는데 이모지가 촌스럽다"는 판단이 더해졌다.

실측해보니 **이모지는 증상이고, 진짜 원인은 타이포 스케일과 대비**였다.

### 실측 — 변경 전

| 위치 | 크기 |
|---|---|
| 이론 본문 `.bx-theory p` | 16px |
| viz 라벨 (읽기/생각/동작) | **11.5px** |
| 탭 (이론/퀴즈/미션) | 13px |
| 전자/정공 라벨 `.la-p em` | 13px |
| 이론관 캡션 `.ba-flow` | 18px |
| 결선 핀 안내 `.dl-pin` | 12.5px |
| 연주판 Hz 표기 | **10.5px** |

모니터 60cm에서 읽는 16px은 프로젝터 3~4m에서 약 28~30px에 해당한다. 본문조차 하한 미달이었고,
11.5px 라벨은 뒷자리에서 읽히지 않았다.

### 대비 (흰 카드 배경 기준)

| 색 | 대비 | 판정 |
|---|---|---|
| `#8a90a0` | 3.2:1 | ❌ WCAG AA(4.5:1) 미달 |
| `#9aa0ac` | 2.6:1 | ❌ |
| `#5a6072` | 6.3:1 | ✓ |

프로젝터는 검정이 뜨고 흰색이 날아가서, 위 두 회색은 배경에 먹힌다.

### 발견한 버그

[`04-games.css`](../src/styles/parts/04-games.css) `.la-p { color: #fff }` 인데
`e⁻`/`h⁺` 텍스트가 흰 카드(`#fbfcfe`) 위에 그대로 올라갔다. **흰 글씨 on 흰 배경 = 안 보임.**
LED 이론관 ① 슬라이드에서 두 글자가 아예 사라져 있었다.

## 2. 무엇을 했나

### 설계 원칙 — 역할별 차등

모든 텍스트가 뒷자리에서 읽힐 필요는 없다. 두 티어로 나눴다.

- **원거리 티어** (제목·핵심 캡션·흐름도 라벨·탭) — 적극 상향
- **책상 티어** (핀 안내·상태 메시지·수치 표기) — 가독 하한(14~15px)까지만

"🔌 초록 LED → D2"는 책상에서 보드 꽂으며 읽는 텍스트다. 같은 비율로 키우면 화면만 답답해진다.

### 변경 파일

```
신규  src/app/icons.js                    아이콘 30종 (인라인 SVG)
신규  src/styles/parts/06-legibility.css  시인성 오버라이드 전부
수정  src/styles/main.css                 @import 한 줄 (맨 끝)
수정  src/scenes/basics.js                스타트 게이트 이론관
수정  src/scenes/sensorRoom.js            이론관 오버레이 + e⁻/h⁺ 버그
```

**기존 CSS는 한 줄도 안 건드렸다.** `main.css` 헤더에 "@import 순서 = 캐스케이드 순서, 절대
바꾸지 말 것 / 덮어쓰려면 더 뒤쪽 파트에 넣는다"고 명시돼 있어 그 규약을 그대로 따랐다.

### 되돌리기

| 무엇 | 방법 |
|---|---|
| 폰트·대비·크기 전부 | `main.css` 의 `06-legibility.css` import 한 줄 주석 처리 |
| 아이콘만 | `icons.js` 의 `USE_SVG = true` → `false` (원래 이모지로 즉시 복귀) |

`USE_SVG` 는 A/B 비교용으로 일부러 남겼다. 껐다 켜면서 나란히 볼 수 있다.

### 아이콘 — 왜 SVG인가

1. 이모지는 OS/브라우저마다 다른 글립으로 그려진다. Windows(Segoe)에서 보고 만든 화면이
   학교 크롬북·맥·태블릿에서 다른 그림이 된다.
2. 디테일이 많아 원거리에서 뭉갠다. 시인성의 무기는 **굵은 스트로크 + 단순한 실루엣**인데
   이모지는 그걸 통제할 수 없다.
3. `currentColor` 라 탭 활성/비활성 같은 상태 변화가 CSS만으로 따라온다.

3D 클레이 렌더 아이콘도 검토했지만, 작은 크기에서 그림자·질감이 뭉쳐 오히려 더 나쁘다.
지금 문제는 "3D 배경 vs 2D 아이콘"이 아니라 **"3D 배경 vs 어중간하게 입체적인 이모지"** 였다.

### 색면 원판 (`iconOrb`)

크게 쓰는 자리(이론 흐름도)는 아이콘만 바꾸지 않고 **색면 원판 + 실루엣**으로 만들었다.
원거리에서는 글립보다 색면이 먼저 읽히기 때문이다. 읽기(파랑)/생각(주황)/동작(노랑) 3단계
구조가 형태만으로 인지된다.

## 3. 범위에서 뺀 것 (의도적)

| 항목 | 이유 |
|---|---|
| ~~`🔌 보드 연결` 버튼, `🔊/🔇` 토글~~ | ~~21곳이 `textContent`로 갱신된다~~ → **나중에 함**(커밋 ⑥). 같은 화면에서 탭은 SVG 인데 음소거 토글은 이모지인 게 실제로 눈에 걸렸다. `innerHTML` 전환은 정적 문자열뿐이라 안전했다 |

| 전시관 말풍선 `guide()` | 이론관이 아니라 캔버스 씬 소속 |

### 4-2. 기계 검증에서 **찾아낸 결함 6건 — 고침**

대비를 실제로 계산해보니 이번 패스가 **새로 넣은 색**에서 6건이 기준 미달이었다.
(비텍스트 3:1 / 본문 4.5:1 기준)

| 대상 | 전 | 후 |
|---|---|---|
| `.ic-think` 칩 아이콘 | `#e07b20` **2.6:1** ❌ | `#a8560c` 4.5:1 ✓ |
| `.ic-act` 전구 아이콘 | `#cf9500` **2.4:1** ❌ | `#8a6100` 5.0:1 ✓ |
| 슬라이드 ③ 입력 라벨 | `#3aa0e0` **2.6:1** ❌ | `#1f6aad` 5.0:1 ✓ |
| 슬라이드 ③ 출력 라벨 | `#e85a8a` **3.0:1** ❌ | `#c22f66` 4.8:1 ✓ |
| 이론 제목 아이콘 | `#ff7a3c` **2.6:1** ❌ | `#e35c10` 3.6:1 ✓ |
| **`h⁺` 원판 흰 글씨** | **2.5:1** ❌ | 4.0~5.3:1 ✓ |

마지막 건이 제일 뼈아프다. §1에서 "흰 글씨 on 흰 배경" 버그를 잡겠다고 만든 원판인데,
**흰 글씨를 밝은 주황 위에 올려서 여전히 안 읽히는 상태**였다. 원인은 그라디언트 기하:
`radial-gradient(circle at 36% 32%, 밝은색, 어두운색)`에서 원 중앙은 그라디언트의 **28% 지점**,
즉 글자가 앉는 자리가 밝은 쪽이었다. 프로젝터는 흰색이 날아가므로 실사용에서 더 나빠진다.

→ 바탕을 `linear-gradient`로 깔고, 광택은 좌상단에서 26%에 사라지는 **별도 레이어**로 분리했다.
구슬 느낌은 유지하면서 글자 자리 대비를 보장한다.

원칙은 §2 그대로다 — **색면(배경)이 3단계 구분을 담당하고 스트로크는 읽히는 것만 담당**하므로,
배경은 밝게 두고 선만 어둡게 내렸다. 색 코딩(파랑/주황/노랑)은 그대로 살아 있다.

재검증: 색을 CSS 파일에서 **직접 파싱해서** 다시 계산했다(내가 의도한 값이 아니라 실제 값 기준).
19개 항목 전부 통과, 실패 0. 빌드 재통과(exit 0).

> ⚠️ `.ic-think`·`.ic-act`는 **이미 육안 확인이 끝난 슬라이드 ①②에 걸린다.** 아이콘 선 색이
> 한 단계 진해졌으니 다시 볼 때 톤을 같이 봐줘야 한다.

## 6. 결정 기록 — 나중에 "고치지" 말 것

### 초기 청크가 53.4 → 60.6 kB 로 커진 것은 의도한 비용이다

크롬 아이콘을 배선하면서(커밋 ⑥) 초기 화면 5개(login·productMain·setup·chapterSelect·hubSelect)가
`icons.js` 를 import 하게 됐다. 그 화면들이 실제로 쓰는 건 2종(음소거 토글)인데 36종 전부가 실린다.
gzip 기준 20.6 → 23.5 kB, **+2.9 kB**.

이 저장소는 초기 청크를 277 → 53 kB 로 줄인 이력이 있어서 회귀처럼 보인다. **회귀가 아니다.**

**왜 그냥 두나 — 비교 대상이 잘못됐다:**

| 항목 | 크기 |
|---|---|
| 이번 증가분 | **2.9 kB** (gzip) |
| 초기 CSS | 138.7 kB (gzip 29.6) — JS 보다 크다 |
| 배경 이미지 한 장 | 100~158 kB |
| `public` 전체 | 3.7 MB |

배경 이미지 한 장이 증가분의 **55배**다. 체감 가능한 차이가 아니다.

**왜 `icons-core.js` 로 쪼개면 안 되나:**

쪼개면 "초기 화면은 core 에서, 지연 로드 화면은 full 에서 import" 라는 규칙이 생기는데,
이 규칙은 **조용히 깨진다**. 누가 `login.js` 에 `icon('flag')` 를 추가하면 폴백 이모지가 나오거나
아무것도 안 나오는데 — 에러도 없고 빌드도 통과한다. 아이콘은 앞으로도 계속 추가될 자리라
이 함정은 반드시 밟는다. 2.9 kB 와 바꿀 것이 못 된다.

**나중에 정말 초기 청크를 줄여야 한다면**, 모듈 분리가 아니라 **아이콘별 named export**(tree-shaking)
가 답이다. 규칙을 기억할 필요가 없어 조용히 깨질 일이 없다. 대신 호출부 약 70곳을 고쳐야 한다.

**그리고 초기 로드를 정말 줄이려면 여기가 아니다** — 레버가 큰 순서로 ① CSS 138.7 kB
(6개 파트가 전부 합쳐져 첫 화면부터 실린다) ② 이미지 3.7 MB.

### 아이콘 도형의 출처가 섞여 있는 것도 의도한 것이다

표준 도형 30종은 Lucide(ISC), 이 제품 고유 개념 6종(`robot`·`board`·`brain`·`press`·`motor`·`digital`)만
직접 그렸다. 기준은 '출처'가 아니라 '제도 규격'이다 — 양쪽 다 viewBox 24 · `fill:none` ·
round cap/join 이고 스트로크만 2.0 → 2.3 으로 통일했다. 실제로 구워보면 구분되지 않는다.

6종을 직접 유지한 근거는 [`src/app/icons.js`](../src/app/icons.js) 헤더에 적어뒀다. 요약하면
Lucide 대응물이 **우리 크기(21~29px)와 우리 의미에서** 더 나빴다 — `mouse-pointer-click` 은
마우스 커서이지 손가락이 아니고, `square-activity` 는 사각파가 아니며, `cog`·`circuit-board` 는
작은 크기에서 더 뭉갠다. 전부 래스터화해서 확인한 결과다.
